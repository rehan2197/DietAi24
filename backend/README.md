# Indian Food Nutrition Estimator — Backend

FastAPI backend implementing the horizontal (request) architecture: a food
photo goes in, vision AI recognizes the dish, nutrient values are retrieved
from a database via RAG — never generated by the AI — and a nutrition
report comes out. When an attribute is invisible to the camera (milk-fat %,
oil vs ghee, biryani region, etc.), the API asks a short clarification
question instead of guessing.

## Stack

| Layer | Technology |
|---|---|
| API framework | FastAPI (Python) |
| Structured data | SQLAlchemy ORM → SQLite (dev) / PostgreSQL (production) |
| Vector search (RAG) | Chroma, with a local TF-IDF+SVD embedder (offline, no API key needed) |
| Vision AI | Gemini API (`google-genai`), with a mock mode for offline dev |
| Nutrition data | Sample IFCT-style dataset (25 foods) — swap for the real IFCT 2017 dataset when available |

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # defaults work out of the box for local dev

python -m scripts.setup_data    # loads the dataset, builds the vector index — run once,
                                 # and again any time app/data/*.csv changes

uvicorn app.main:app --reload   # http://127.0.0.1:8000
```

Interactive API docs (Swagger UI) are auto-generated at `http://127.0.0.1:8000/docs`.

Run the test suite (fully offline, no API key needed — uses `debug_description`):
```bash
pytest -v
```

## Running without a Gemini API key

By default `GEMINI_API_KEY` is empty in `.env`, which puts the vision step
in **mock mode**: instead of a photo, send a `debug_description` form field
(plain text describing the food) and the rest of the pipeline — retrieval,
clarification, computation — runs exactly as it would for a real photo.
This is what the test suite uses, and it's the fastest way for a frontend
developer to build against this API before a Gemini key is available.

To enable live photo recognition, set `GEMINI_API_KEY` in `.env`.

## API Reference

Base URL: `http://127.0.0.1:8000/api/v1`

### `POST /estimate`

The core pipeline endpoint. `multipart/form-data`.

**Request fields (all optional, see usage patterns below):**

| Field | Type | Purpose |
|---|---|---|
| `image` | file | The food photo. Required for live recognition. |
| `debug_description` | string | Bypass vision AI with plain text (offline dev/testing). |
| `portion_grams` | float | Override the default portion size. |
| `clarification_attribute` | string | From a previous `needs_clarification` response. |
| `clarification_answer` | string | The option the user picked. |

**Usage pattern 1 — normal photo request:**
```bash
curl -X POST http://127.0.0.1:8000/api/v1/estimate \
  -F "image=@plate.jpg"
```

**Usage pattern 2 — dev/testing without a photo:**
```bash
curl -X POST http://127.0.0.1:8000/api/v1/estimate \
  -F "debug_description=a plate of chicken biryani"
```

**Response — direct match (`status: "ok"`):**
```json
{
  "status": "ok",
  "foods": [
    {
      "food_code": "IF016",
      "food_name": "Idli",
      "region_variant": "Standard",
      "matched_confidence": 0.87,
      "portion_unit": "piece",
      "portion_grams": 40.0,
      "nutrients": {
        "calories_kcal": 39.0, "protein_g": 2.0, "carbs_g": 7.8,
        "fat_g": 0.2, "fiber_g": 0.5, "calcium_mg": 5.0, "iron_mg": 0.3
      }
    }
  ],
  "totals": { "...": "same shape as nutrients, summed across all foods" },
  "clarification": null,
  "notes": "Recognized as: steamed idli"
}
```

**Response — ambiguous match (`status: "needs_clarification"`):**
```json
{
  "status": "needs_clarification",
  "foods": [],
  "totals": null,
  "clarification": {
    "attribute": "Chicken Biryani",
    "question": "Which regional style is this biryani?",
    "options": ["Awadhi/Lucknowi", "Hyderabadi", "Kolkata"]
  },
  "notes": "Recognized as 'a plate of chicken biryani', matched to 'Chicken Biryani' — attribute unclear."
}
```

**Frontend flow for `needs_clarification`:** show the `question` with the
`options` as buttons/choices, then re-submit the *same* request but with
`clarification_attribute` and `clarification_answer` set instead of
`image`/`debug_description` — no need to resend the photo.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/estimate \
  -F "clarification_attribute=Chicken Biryani" \
  -F "clarification_answer=Kolkata"
```

**Response — no match (`status: "no_match"`):** `foods` is empty, check
`notes` for why (no database entry, empty vector index, missing API key
with no image, etc.)

### `GET /foods/search?q={text}&top_k=5`

Semantic search over the food database directly — same retrieval logic the
estimate pipeline uses internally. Useful for a "browse the database"
screen or debugging matches. Returns a list of full `FoodOut` objects.

### `GET /foods/{food_code}`

Fetch one food entry by its exact code (e.g. `IF001`). 404 if not found.

### `GET /health`

Basic liveness check: `{"status": "ok", "app": "..."}`.

## Project structure

```
app/
  main.py              FastAPI app, CORS, startup, routers
  config.py            Settings (env-driven)
  database.py           SQLAlchemy engine/session
  models.py            Food, PortionUnit ORM models
  schemas.py           Pydantic request/response contracts
  data/
    ifct_sample.csv       Sample nutrition dataset (25 foods) — swap for real IFCT
    portion_mapping.csv   Indian unit -> grams (katori, roti, plate, ...)
  services/
    vision_service.py       Gemini wrapper + mock mode
    embedding.py             Local TF-IDF+SVD embedder
    retrieval_service.py     Chroma-backed RAG search
    estimation_service.py    Clarification logic + nutrient math
    ingest_service.py        Loads CSVs into SQL + builds vector index
  routers/
    estimate.py          POST /estimate (the core pipeline)
    foods.py              GET /foods/search, GET /foods/{code}
scripts/
  setup_data.py         Run once to populate DB + vector index
tests/
  test_estimate.py      End-to-end tests (offline, via debug_description)
```

## Swapping in the real IFCT dataset

Replace `app/data/ifct_sample.csv` with a file using the same column
headers (or adjust `ingest_service.load_foods_csv`), then re-run
`python -m scripts.setup_data`. Nothing else in the pipeline needs to
change — the SQL schema, vector index, and API are all dataset-agnostic.

## Known limitations (by design, at this milestone)

- Single-item recognition only — a photo with multiple separate dishes
  (e.g. a thali) is not yet decomposed into components. This is a planned
  next step, not a bug.
- The sample dataset covers 25 foods for demonstration; the full IFCT 2017
  dataset covers 528 foods.
- The local TF-IDF+SVD embedder is a pragmatic, fully-offline stand-in for
  a hosted embedding model — swap in Gemini/OpenAI embeddings by replacing
  `TextEmbedder` in `app/services/embedding.py` behind the same interface
  if retrieval quality needs to improve beyond the prototype stage.
